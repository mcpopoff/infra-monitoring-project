
Информация о задании

Форма проверки: задание с проверкой преподавателем.
Цели задания: Закрепить навыки написания Bash-скриптов, анализа сетевого трафика, работы с Git, настройки CI/CD и контейнеризации готовых сервисов.
Правила приёма работы:
В форму ответа на платформе прикрепите две ссылки:
Ссылка на публичный репозиторий GitHub
Ссылка на отчёт (word или PDF) со скриншотами и дампом трафика
В отчёте обязательно должны быть:
Скриншот Wireshark с отфильтрованным HTTP-трафиком
Вывод работы analyze_logs.sh в терминале
Скриншот работающих контейнеров (docker-compose ps)
Скриншот успешного CI/CD пайплайна в GitHub
Пример работы check_api.sh с валидным и невалидным URL
 
Описание задания
Легенда

Вы работаете DevOps-инженером в стартапе. Команда разработала простой API-сервис (echo-сервер), и ваша задача — настроить систему мониторинга его доступности, автоматизировать анализ логов и подготовить контейнеризированную среду для развертывания.
Пошаговое выполнение
Этап 1. Git Workflow и организация проекта

    Создайте публичный репозиторий на GitHub с названием infra-monitoring-project.
    Создайте ветку main (защищённую) и рабочую ветку feature/monitoring. Всю работу ведите в feature/monitoring.
    Инициализируйте проект файлами README.md, .gitignore (исключите логи, временные файлы, артефакты сборки).
    В конце работы создайте Pull Request из feature/monitoring в main с подробным описанием изменений.

Этап 2. Анализ сетевого трафика

    Установите Wireshark на свою рабочую машину.
    Запустите захват трафика на сетевом интерфейсе.
    Выполните несколько HTTP-запросов к любому публичному API (например, https://httpbin.org/get или https://api.github.com) с помощью curl или браузера.
    Отфильтруйте трафик по протоколу HTTP/HTTPS.
    Сохраните дамп трафика (.pcapng) и приложите его к отчёту. В отчёте укажите:
        Какие IP-адреса участвовали в обмене
        Какие HTTP-методы использовались
        Какие коды ответов вернул сервер

Этап 3. Bash-скрипты для мониторинга и анализа

    Скрипт мониторинга API (check_api.sh):
        Принимает URL API как аргумент командной строки
        Делает HTTP-запрос через curl
        Проверяет код ответа (ожидается 200)
        Выводит статус: “API доступен” или “API недоступен, код ответа: XXX”
        Возвращает код возврата 0 при успехе, 1 при ошибке

    Скрипт анализа логов (analyze_logs.sh):
        Генерирует тестовый файл access.log (минимум 300 строк) с записями вида:
        192.168.1.10 - - [15/Aug/2026:10:15:32] “GET /api/users HTTP/1.1” 200
        10.0.0.5 - - [15/Aug/2026:10:15:33] “POST /api/login HTTP/1.1” 401
            С помощью grep, awk, sort, uniq выводит:
            Общее количество запросов
            Топ-3 IP-адреса с наибольшим числом запросов
            Количество запросов с кодами 4xx и 5xx
        Использует регулярные выражения для парсинга IP-адресов

    Сделайте оба скрипта исполняемыми (chmod +x) и протестируйте их работу.

Этап 4. Docker Compose для стека мониторинга

    Создайте файл docker-compose.yml в корне проекта.
    Опишите два сервиса, используя готовые образы из Docker Hub:
        api: образ hashicorp/http-echo с текстом “Monitoring Service Active” на порту 8080
        proxy: образ nginx:alpine, который проксирует запросы с порта 80 на порт 8080 сервиса api
    Настройте внутреннюю сеть Docker для связи контейнеров.
    Проверьте работу командой docker-compose up -d и выполните curl http://localhost:80 — должен вернуться текст “Monitoring Service Active”.

Этап 5. CI/CD Pipeline (GitHub Actions)

    Создайте директорию .github/workflows/ и файл ci.yml.
    Настройте пайплайн, который при создании Pull Request выполняет:
        Проверку синтаксиса Bash-скриптов: bash -n check_api.sh и bash -n analyze_logs.sh
        Тестирование скрипта мониторинга: запуск check_api.sh https://httpbin.org/status/200 с ожиданием кода возврата 0
    Добейтесь успешного прохождения пайплайна (зелёная галочка в GitHub).

Этап 6. SSH и SCP

    В README.md опишите процесс безопасной передачи файлов проекта на удалённый сервер:
        Генерация SSH-ключей (ssh-keygen)
        Копирование публичного ключа (ssh-copy-id)
        Передача архива проекта через scp или tar + ssh
